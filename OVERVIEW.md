Model providers manages API endpoints, credentials and selected models for Claude Code, Codex, OpenCode, Pi and OMP in Paseo. It adds independent provider entries to Paseo's normal agent picker and a screen for configuring providers and starting sessions. Existing subscription logins and agent presets remain available; custom APIs use the selected provider's API quota.

Requires Paseo 0.12.0 or newer on the daemon and clients, and each selected agent CLI already installed on the daemon's PATH. The plugin does not install external software at runtime. The interface includes English and Simplified Chinese, with an in-screen language selector; the initial language follows the device locale. The sidebar entry uses a bilingual name on Paseo 0.12.

Add or edit a provider in a popup, choose its protocol and select models from its catalog or enter model IDs manually. Anthropic Messages supports Claude Code, OpenCode, Pi and OMP; OpenAI Responses supports Codex, Pi and OMP; Chat Completions supports OpenCode, Pi and OMP. Anthropic authentication supports either x-api-key or Bearer tokens. The plugin does not translate between protocols. Changes apply to new or reopened sessions, without switching a running session's endpoint. Disabling a provider does not stop existing sessions.

Credentials are stored in plaintext on the daemon under PASEO_HOME/model-providers/suppliers.json (directory mode 700, file mode 600), and in the generated Paseo provider environment configuration. Users able to read those files can access the keys. Saved keys are not returned to the interface; leaving the key blank when editing keeps the previous value. Endpoints without authentication can use an empty key. The plugin updates only its own provider aliases through the Paseo SDK and rejects collisions with other configurations. It does not read or change official authentication files.

Fetching models sends an authenticated GET request to the configured endpoint's /v1/models path, without duplicating /v1 when already present. Anthropic catalogs support pagination. Connection tests send a short “Reply OK.” prompt and a tool definition to the configured endpoint and may consume billable tokens. The test never executes the tool. Starting an agent sends prompts, code context and tool results to the configured model provider according to that agent's behavior. The plugin has no telemetry service; the endpoint and its data policies are chosen by the user.

Model catalogs do not prove invocation permission. A successful connection test checks only basic protocol response structure; streaming, end-to-end agent tool use, MCP integration and model quality are not certified. Pi/OMP models are registered through a private local extension with text input, reasoning disabled and unknown pricing; zero cost metadata means unknown rather than free. Enter context and output limits from your provider's specifications. The wider desktop editor uses the current host dialog structure and may need adjustment if Paseo changes that structure. Actual compatibility depends on the installed CLI and provider API.
