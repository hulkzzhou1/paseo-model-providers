# Domain documentation

This repository uses a single context: `GLOSSARY.md` at the repository root and architecture decision records in `docs/adr/`.

Before exploring a domain, read the glossary and the ADRs relevant to the area. If these files are absent, proceed silently. Create them lazily through `/domain-modeling` when terminology or a design decision has been resolved.

Use glossary terms consistently in issue titles, design proposals, hypotheses, and tests. If a needed concept is missing, reconsider the term or note the gap for `/domain-modeling`.

When a proposal conflicts with an existing ADR, identify that ADR and explain why the decision should be reopened.
